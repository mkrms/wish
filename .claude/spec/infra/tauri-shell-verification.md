# 機能外仕様: Tauri 殻の実機検証手順（tauri-shell-verification）

Wish の **P2（Tauri 完全版）** で実装済みのネイティブ殻機能を、**CI が生成した installer を実機にインストールして**合否判定するためのチェックリスト。判断の経緯は decisions-log D-003 / D-010。

> CI（GitHub Actions）はビルドまでは担えるが、ホットキー・トレイなどの**対話的な挙動は自動検証できない**。本手順はユーザーが実機（Windows）で installer を実行し、各項目の「操作 → 期待結果」を確認して埋めるためのもの。

## 前提・対象
- **対象機能**: グローバルホットキー / トレイ常駐 / ウィンドウ × でトレイ退避 / 単一起動 / 永続化。
- **根拠**: `src-tauri/src/lib.rs`（殻の挙動）/ `src/tauri.ts`（フロント側の購読・再登録）/ `src-tauri/capabilities/default.json`（権限）。
- **検証ビルド**: `.github/workflows/release.yml` の `workflow_dispatch`（artifact）またはタグ push（ドラフトリリース）で生成された `.msi` または NSIS `.exe`。distribution.md のリリース手順 6 に対応。
- **検証環境**: Windows 11（WebView2 ランタイム導入済み）。クリーンに近い状態が望ましい（既存の Wish は事前にアンインストール / プロセス終了）。

## 1. グローバルホットキー（既定 Alt+Space）
根拠: `lib.rs` `setup()` で `Alt+Space` を登録 → ハンドラが `show_and_capture()`（show / unminimize / set_focus / `emit("toggle-palette")`）。フロントは `tauri.ts` で `toggle-palette` を購読し `openPalette()`。設定変更は `set_global_shortcut` コマンドで `unregister_all` → `register`。

| # | 操作 | 期待結果 | 結果(OK/NG) | 備考 |
|---|---|---|---|---|
| H-1 | Wish ウィンドウを**最小化**した状態で、別アプリ（ブラウザ等）を前面にして `Alt+Space` を押す | Wish ウィンドウが前面化し、**コマンドパレットが開く** | | |
| H-2 | Wish を**トレイへ隠した**状態（× で閉じた後）で `Alt+Space` を押す | ウィンドウが再表示され前面化し、パレットが開く | | |
| H-3 | 設定 → クイック起動ホットキーを別キー（例 `Ctrl+Shift+Space`）に変更 | 変更が即時保存される（再起動不要） | | |
| H-4 | 変更後、**新しいキー**を押す | 新キーでウィンドウ前面化＋パレットが開く（`set_global_shortcut` で再登録された） | | |
| H-5 | 変更後、**旧キー `Alt+Space`** を押す | 反応しない（旧登録が解除されている） | | |

## 2. トレイ常駐
根拠: `lib.rs` `TrayIconBuilder`。左クリック → `toggle_window()`（表示/非表示トグル）。`show_menu_on_left_click(false)` のためメニューは右クリックで開く。メニュー項目「Wish を開く」→ `show_and_capture()`、「終了」→ `app.exit(0)`。

| # | 操作 | 期待結果 | 結果(OK/NG) | 備考 |
|---|---|---|---|---|
| T-1 | タスクトレイに Wish アイコンがある（ホバーで "Wish" ツールチップ） | アイコンとツールチップが表示される | | |
| T-2 | ウィンドウ表示中にトレイアイコンを**左クリック** | ウィンドウが**非表示**になる | | |
| T-3 | 非表示状態でトレイアイコンを**左クリック** | ウィンドウが**再表示**され前面化する | | |
| T-4 | トレイアイコンを**右クリック** | メニューが開き「Wish を開く」「終了」が表示される | | |
| T-5 | メニュー「**Wish を開く**」を選択 | ウィンドウが表示され前面化（パレットも開く＝`show_and_capture`） | | |
| T-6 | メニュー「**終了**」を選択 | アプリが完全終了する（トレイアイコンが消え、プロセスが残らない） | | |

## 3. ウィンドウ × でトレイ退避
根拠: `lib.rs` `on_window_event` の `CloseRequested` → `api.prevent_close()` + `window.hide()`（終了せずトレイへ）。

| # | 操作 | 期待結果 | 結果(OK/NG) | 備考 |
|---|---|---|---|---|
| C-1 | ウィンドウ右上の **×（閉じる）** をクリック | アプリは**終了せず**、ウィンドウが非表示になりトレイに残る | | |
| C-2 | C-1 の後、トレイ左クリックまたはホットキーで再表示 | ウィンドウが復帰する（プロセスは継続していた） | | |

> 完全終了はトレイメニューの「終了」（T-6）でのみ行う、という挙動を確認する。

## 4. 単一起動
根拠: `lib.rs` `tauri_plugin_single_instance::init`。二重起動時はコールバックで `show_and_capture()`（既存ウィンドウを前面化）。

| # | 操作 | 期待結果 | 結果(OK/NG) | 備考 |
|---|---|---|---|---|
| S-1 | Wish 起動中に、もう一度 Wish を起動（スタートメニュー / `.exe` ダブルクリック） | **新しいウィンドウは増えず**、既存ウィンドウが前面化する（パレットも開く） | | |
| S-2 | S-1 の後、ウィンドウ／トレイが**1 つだけ**であることを確認 | アイコン・ウィンドウともに 1 インスタンスのみ | | |

## 5. 永続化（localStorage）
根拠: Zustand `persist`（`src/store.ts`）。WebView の localStorage にデータ（tasks / projects / memos / settings / seq）が保存される。

| # | 操作 | 期待結果 | 結果(OK/NG) | 備考 |
|---|---|---|---|---|
| D-1 | タスクを 1 件追加、メモを 1 件保存、設定（例: 週開始曜日 or ホットキー）を変更 | いずれも反映される | | |
| D-2 | トレイメニュー「終了」でアプリを完全終了 → 再起動 | 追加したタスク・メモ・変更した設定が**残っている** | | |
| D-3 | （任意）OS を再起動 → Wish を起動 | データが残っている | | |

## 備考
- NG が出た項目は、`src-tauri/src/lib.rs`（殻）/ `src/tauri.ts`（フロント購読）/ `capabilities/default.json`（権限不足）のいずれかを疑う。とくにホットキー無反応は権限（`global-shortcut:allow-register`）かアクセラレータ表記（`tauri.ts` の `toAccelerator`）を確認する。
- 本手順の各「結果」「備考」欄はユーザーが埋める。検証結果は必要に応じて報告へ転記する（このファイルは雛形として再利用する）。
