# 機能仕様: タスク入力記法（明示プレフィックス＋候補サジェスト）

クイック追加・コマンドパレットの入力解析を、**自動推測から明示プレフィックス方式へ移行**する。
判断の経緯は decisions-log **D-031**。対象は `src/lib/parse.ts` と、それを使うすべての入力欄。

---

## 1. 背景（なぜ変えるか）

現行の `parse()` は日付・時刻を**裸のテキストから推測**するため、意図しない誤爆が起きる。

| 入力 | 現行の解釈 | 原因 |
|---|---|---|
| `入出金` | **金曜日** | `/(月\|火\|水\|木\|金\|土\|日)曜?/` の `曜` が任意で、単独漢字にマッチする |
| `日報` | 日曜日 | 同上 |
| `月次レポート` | 月曜日 | 同上 |
| `3時間かかる` | 3:00 | `時` の後ろを見ていない |
| `1/2 に分割` | 1月2日 | 前後の文脈を見ていない |
| `高優先度の整理` | 優先度=高 | `高優先` を裸で解釈している |

一方 **`#プロジェクト` と `!優先度` はプレフィックス必須のため誤爆していない**。壊れているのは日付・時刻（と `高優先`）だけであり、これらを同じ土俵（明示プレフィックス）へ揃える。

タイプ量が増える分は、**`@` `#` `!` を打った時点で候補を出す**ことで相殺する（記法を覚える必要をなくす）。

---

## 2. 記法（すべて明示プレフィックス）

半角・全角（`@＠` `#＃` `!！`）の双方を受ける。トークンは**空白または別のプレフィックスまで**。

### 2.1 `@` — 日付・時刻

| 記法 | 意味 | 例（今日=8/3 の場合） |
|---|---|---|
| `@今日` `@明日` `@明後日` | 相対日 | 8/3・8/4・8/5 |
| `@今週末` | 次の土曜 | 8/9 |
| `@来週` | 7 日後 | 8/10 |
| `@月`〜`@日` / `@月曜` / `@金曜日` | **次に来る**その曜日（今日と同じ曜日なら 7 日後） | `@金` → 8/8 |
| `@8/10` | 月/日（年は今年） | 8/10 |
| `@+3d` | N 日後 | 8/6 |
| `@15:00` `@15時` `@15時30分` | 時刻 | 15:00 / 15:30 |

- 日付と時刻は**別トークンで併記**できる: `設計レビュー @明日 @15:00`
- 同種が複数あるときは**最初の 1 つ**を採用する（残りはタイトルに残さず捨てる）。
- **解釈できない `@xxx` はタイトルにそのまま残す**（入力が黙って消えないことを優先）。

### 2.2 `#` — プロジェクト
`#名前`。空白を除いて比較し、**前方一致 → 部分一致**の順で最初に見つかったプロジェクトを採用する。
現行の逆方向あいまい一致（`q.indexOf(p.name.slice(0,2))`）は**廃止**（候補サジェストがあるため不要で、誤爆源になる）。
一致するプロジェクトが無い `#xxx` はタイトルに残す。

### 2.3 `!` — 優先度
`!高` `!中` `!低`。**`高優先` の裸解釈は廃止**。

### 2.4 廃止するもの
- 裸の `今日` `明日` `明後日` `今週末` `来週` `金曜` `15時` `8/10` `+3d` の解析
- `高優先` の解析
- `まで` / `までに` のタイトルからの除去（裸解析の名残。**タイトルにそのまま残す**）

> 既に保存済みのタスクには影響しない（解析は入力時のみ）。

## 3. 候補サジェスト

### 3.1 動作
- カーソル直前のトークンが `@` `#` `!` で始まっているとき、入力欄の**直下にドロップダウン**を出す。
- 入力を続けると**前方一致で絞り込む**（`@明` → 明日 / 明後日）。
- 候補が 0 件になったら閉じる。

| キー | サジェスト表示中 | 非表示時 |
|---|---|---|
| `↑` `↓` | 候補を移動 | （通常の挙動） |
| `Enter` / `Tab` | **候補を確定**（タスクは追加しない） | タスクを追加 |
| `Esc` | **サジェストを閉じる**（パレットは閉じない） | 既存の挙動（パレットを閉じる等） |
| その他 | 通常の入力 | |

- クリックでも確定できる。
- 確定するとトークンが置換され、カーソルはその直後（＋半角スペース）へ移る。

### 3.2 候補の内容

| トリガ | 候補 |
|---|---|
| `@`（query 空） | 今日 / 明日 / 明後日 / 今週末 / 来週 / 月曜〜日曜。**各候補に実際の日付をヒント表示**（例「明日 → 8/4」） |
| `@` ＋ 数字始まり | 入力に応じた動的候補。`@15` → `15:00`（時刻）、`@8/10` → `8月10日`、`@+3` → `3日後` |
| `#` | プロジェクト一覧（色ドット付き。前方一致で絞り込み） |
| `!` | 高 / 中 / 低 |

- 表示は最大 8 件（超過分はスクロール）。

### 3.3 適用範囲
`parse()` を使うすべての入力欄に適用する（ユーザー選択: 全適用）。

| 場所 | 変更 |
|---|---|
| コマンドパレット（`CapturePalette`） | サジェスト追加。既存の「解析 →」チップは維持 |
| 各リストのクイック追加（`ListView`） | サジェスト追加。**「解析 →」チップも同様に表示**（現在は無いので揃える） |

---

## 4. 実装方針

ロジックと描画を分離するプロジェクト方針に従い、**トークン抽出・候補生成・置換はすべて純粋関数**にする。

| ファイル | 役割 |
|---|---|
| `src/lib/parse.ts`（改修） | 明示プレフィックスのみを解析。裸解析を全廃 |
| `src/lib/suggest.ts`（新規） | `activeToken()` / `suggestFor()` / `applySuggestion()` の純粋関数 |
| `src/components/TaskInput.tsx`（新規） | `input` ＋ サジェストのドロップダウンをまとめた共用部品。パレットとクイック追加の双方から使う |
| `src/components/ParsePreview.tsx`（新規） | 「解析 →」チップ（現在 `CapturePalette` にインラインで書かれているものを切り出して共用） |

プレースホルダ／ヒントも新記法に更新する。

- パレット: `設計レビュー @明日 @15:00 #ECサイト !高`
- クイック追加: `タスクを追加  例: 障害報告書 @金曜 #顧客A !高`
- パレットのフッターに記法ヒント（`@ 日付 / # プロジェクト / ! 優先度`）を出す。

---

## 5. 受け入れ条件

1. `入出金` `日報` `月次レポート` `3時間かかる` `1/2 に分割` `高優先度の整理` を入力しても、**日付・時刻・優先度が一切付かない**（タイトルは入力そのまま）。
2. `障害報告書 @金曜 #顧客A !高` で、次の金曜・顧客A・優先度高が付き、タイトルは `障害報告書` になる。
3. `設計レビュー @明日 @15:00` で due=明日・time=15:00 になる。
4. 解釈できない `@xyz` / 一致しない `#未登録` はタイトルに残る。
5. `@` を打つと候補が出て、↑↓ と Enter/Tab で確定でき、Enter でタスクが誤って追加されない。
6. サジェスト表示中の Esc で候補だけが閉じ、パレットは開いたままになる。
7. パレットとクイック追加の**両方**で 1〜6 が同じように動く。
8. `tsc` / `npm run build` / `npm test` が通り、ブラウザでコンソールエラーが出ない。
